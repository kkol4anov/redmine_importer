# Импорт XLSX

Реализация подготовлена для `master` на коммите
`c1bd2ca6c7fb936c40e7f5588d5fe38352880b15`.

## Установка патча

В каталоге `plugins/redmine_importer` проверьте и примените скачанный патч:

```sh
git apply --check /path/to/redmine_importer_xlsx_master.patch
git apply /path/to/redmine_importer_xlsx_master.patch
```

Затем из корневого каталога **Redmine**, а не плагина:

```sh
bundle install
bundle exec rake tmp:cache:clear RAILS_ENV=production
```

Перезапустите Redmine способом, принятым для вашего сервера. Новые миграции БД
не требуются. Патч добавляет `Gemfile` плагина с `roo ~> 2.10.1` (линия,
совместимая с Ruby 2.7). Зависимости Roo: Nokogiri и rubyzip. Excel, LibreOffice,
Python и отдельный процесс конвертации на сервере не нужны. В закрытом контуре
нужно заранее подготовить gem-пакеты под Ruby и ОС сервера.

Если `git apply --check` сообщает конфликт, не применяйте патч принудительно:
нужно сопоставить его с вашей версией. Другие ветки, включая `auto-crud`, могут
отличаться от указанного коммита `master`.

## Использование

1. Выберите файл `.xlsx` на обычной странице импорта.
2. Введите точное название листа или оставьте поле пустым: будет взят первый
   лист в порядке книги. За один импорт обрабатывается только один лист.
3. Нажмите загрузку. Привяжите колонки к полям Redmine, выберите режим и
   проверьте предпросмотр. Название выбранного листа показано над настройками.
4. Запустите импорт обычной кнопкой.

Кодировка, разделитель и кавычки нужны только для CSV. Для XLSX эти поля
скрываются, а сервер задаёт внутренние параметры самостоятельно. При отключённом
JavaScript сервер всё равно определяет формат по расширению файла.

Первая непустая строка выбранного листа — заголовки. Заголовки очищаются от
пробелов по краям и должны быть уникальными и непустыми. Пустые строки и пустое
форматирование в конце строки не создают задачи. Пропущенная ячейка внутри строки
остаётся пустой: следующие значения не сдвигаются влево. Данные в колонке без
заголовка вызывают ошибку. Отдельный заголовок отчёта перед таблицей нужно удалить.

Скрытые и отфильтрованные строки также читаются. Скрытый первый лист тоже может
быть выбран по умолчанию: при необходимости задайте название явно.

## Преобразование значений

| Значение в Excel | Значение для импорта |
| --- | --- |
| Текст, кириллица, переносы строк, кавычки | Сохраняются |
| Текстовый код `003.0006.201` | `003.0006.201` |
| Число `123.0` | `123` |
| Дробное число `1.25` | `1.25` |
| Число `123` с форматом `000000` | `000123` |
| Дата Excel | `YYYY-MM-DD`, с учётом календаря книги 1900/1904 |
| Дата со временем | `YYYY-MM-DD HH:MM:SS` |
| Время | `HH:MM:SS` |
| Логическое значение | `1` или `0` |
| Формула | Сохранённый результат вычисления |
| Процент `25%` | Исходное число `0.25` |

Сложные пользовательские числовые форматы не воспроизводятся. Исключение —
маска только из нулей для кодов с ведущими нулями. Идентификаторы, особенно
длиннее 15 цифр, лучше хранить в Excel как текст с самого начала. Потерянную
Excel точность восстановить невозможно. Для поля «Готовность» указывайте число
от 0 до 100, например `25`, без процентного формата.

Формулы не выполняются на сервере, внешние ссылки не запрашиваются. Перед
импортом пересчитайте и сохраните книгу в Excel/LibreOffice. Отсутствие кэша
результата или ошибка Excel (`#REF!`, `#DIV/0!` и т. п.) останавливают загрузку
с указанием ячейки. Проверки формул, ошибок и объединений относятся к выбранному
листу. Свежесть сохранённого результата формулы автоматически не определяется.

Объединённые ячейки на выбранном листе запрещены: отмените объединение и
заполните каждую строку. Старый `.xls`, `.xlsm`, зашифрованные книги и повреждённые
архивы не поддерживаются.

## Ограничения и совместимость с текущим импортом

- До 4 МиБ для загруженного XLSX и отдельно до 4 МиБ для полученных CSV-данных.
  Второе ограничение соответствует существующему полю хранения плагина.
- До 64 МиБ после распаковки, 2000 элементов ZIP и 1024 колонок.
- Количество непустых строк данных ограничено существующей настройкой плагина
  `max_csv_rows` (по умолчанию 5000). Проверка останавливается на первой лишней
  строке: в сообщении указано обнаруженное к этому моменту количество.
- DTD и определения XML-сущностей отклоняются до обработки Roo.
- Неверная книга отклоняется до удаления предыдущего `ImportInProgress`.

XLSX преобразуется в UTF-8 CSV в памяти, затем передаётся существующему
механизму плагина. Привязка полей, составные ключи, поиск дублей, родительские
связи, создание/обновление/удаление, прогресс и отмена используют прежний код.
В БД сохраняются только подготовленные CSV-данные, исходный XLSX не хранится.
Номера строк в результатах — номера непустых строк данных после заголовка,
начиная с 1. Из-за пропуска пустых строк они могут отличаться от номеров Excel.

## Проверка

Автономные тесты реального ZIP/XML-чтения:

```sh
# Из каталога плагина, при установленных roo и minitest
ruby test/unit/xlsx_reader_test.rb
```

Проверено на Ruby 3.2.3, Roo 2.10.1, rubyzip 2.3.2 и Nokogiri 1.16.2:
17 тестов, 41 проверка, без ошибок. Проверен синтаксис изменённого контроллера.
Добавлены функциональные тесты цепочки XLSX → привязка → создание задачи и
отказа при превышении лимита. Полный запуск этих тестов требует приложения
Redmine с тестовой БД и здесь не выполнялся.

На тестовом Redmine после установки проверьте загрузку небольшой XLSX-книги,
создание задач, повторную загрузку с обновлением и обычный CSV. Для проверки
удаления используйте только специально созданные тестовые задачи.

## Откат

При отсутствии последующих правок в затронутых файлах, из каталога плагина:

```sh
git apply -R --check /path/to/redmine_importer_xlsx_master.patch
git apply -R /path/to/redmine_importer_xlsx_master.patch
```

Затем выполните `bundle install` в корне Redmine и перезапустите приложение.
Откат кода не отменяет уже выполненные операции с задачами.
